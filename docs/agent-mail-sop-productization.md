# Agent Mail 可复用 SOP 与产品化机会

日期：2026-09-11。来源见[会话复盘](agent-mail-2026-09-11-retrospective.md)。
下面 SOP 是本次经验归纳；产品化条目是建议，未实现、未授权自动操作。
生产操作以[完整迁移 SOP](agent-mail-production-migration-plan.md)及对应所有者授权为准。

## SOP 清单与结论

### S1 版本与市场来源核对

1. 分开记录源码版本、已发布版本、本机已安装版本、市场条目安装目标。
2. 读取已安装 package 与 tarball pin；核对 Release 摘要和实际下载内容。
3. 检查市场对应版本的解析顺序，不能从卡片描述、已安装标识或 npm 是否存在推断目标。
4. 记录目录 PR 状态、缓存刷新与实际安装验证各自是否完成。

输出：四状态对照表、字节来源、未完成项。结论：市场描述过期不等于本机代码过期。

### S2 逐页产品与技术信息边界审查

1. 列出日常页、详情、设置、管理、工具卡片及空/加载/异常状态。
2. 每个发现标注截图、源码或浏览器实测证据，注明数据来源和可用能力。
3. 保留用户可行动的信息；技术标识/诊断折叠；不支持、未配置、失败和过期分别处理。
4. 检查接口和错误输入，不能以视觉隐藏替代访问控制或脱敏。
5. 生成任务、责任范围和正/负向验收矩阵；颜色必须同时有文字/图标。

输出：P01–P16 式页面矩阵。结论：先简化信息层级，再增加颜色；不能伪造在线状态。

### S3 精确包与跨版本升级验证

1. 独立准备 provider 与插件的归档、版本、SHA-256 和文件 allowlist。
2. 按运行时要求在干净前缀安装原生依赖，验证已安装文件与归档相符。
3. 在显式隔离 DSH_HOME 移除旧独立 UI，安装统一包，验证一 MCP/一 UI。
4. 对本次实际旧版本做升级与回退，不以另一个预览版本替代。
5. 运行合同、缺失可执行文件、重复命名空间、移除清理及真实浏览器验证。

输出：精确归档验收记录。结论：源码测试通过不等于归档安装通过。

### S4 停写备份与保留新邮件的软件回退

1. 记录生产/预览身份与依赖入口；盘点 socket 激活和邮箱写入者。
2. 在授权范围停止生产入口、代理和主服务；核实实际停写，越界依赖不得擅停。
3. 保存部署文件、运行时和停止后的真实 home；SQLite 使用一致性备份方式并验收恢复副本。
4. 在副本上让新版写入，再用旧版读/ack，验证向后兼容；不可将演练副本提升为生产。
5. 切换后可能有新写入时，只回退软件/配置并保留当前邮箱；数据库恢复另行决策。

输出：T0 账本、恢复验证与软件回退步骤。结论：备份存在和主文件哈希都不是数据恢复证明。

### S5 邮箱交付、任务回执与未知结果验证

1. 用合成稳定标记发送一次，确认真实收件人 inbox 和发送历史。
2. 由 assignee 领取并给 origin 发 done/error，再确认原任务终态与通知自身投递状态。
3. 模拟“提交已成功、随后刷新失败”，验证正确提示和手动恢复。
4. 发送返回失败/超时先核实已接受结果，不能直接重发；分页检索到明确结果才继续。
5. 验证关闭重开、进程重启和故障恢复；保留测试结果和精确计数。

输出：L1–L5 式证据矩阵。结论：已提交、已确认收悉、任务完成和自动执行是不同事实。

### S6 浏览器与故障注入工具的可信度

1. 有界等待 HTTP/API 就绪，再驱动页面；不要把进程启动返回当应用 ready。
2. 按版本与页面区域定位，等待控件可操作；避免误触 DSH 模型输入框。
3. 断连注入采用明确阶段信号，确认探针在 down 窗口内执行。
4. 测试失败先保存受保护证据，区分产品回归与选择器/布局/时序假设；不能放宽业务断言掩盖缺陷。
5. 明确 loopback、LAN、TLS 挑战和认证浏览器各自覆盖范围。

输出：脚本问题与产品问题分别归档。结论：一个测试脚本成功摘要不能替代完整路径证据。

### S7 委派与接续

1. 主代理定义独立、有限的 worker 范围与共享文件归属。
2. worker 回报原始结果及 not_run/失败，不合并为一个含糊 PASS。
3. 主代理核对完整差异、关键证据与最终验收；能力不可用时如实标明替代方式。
4. 接续文档包含当前状态、未提交修改、执行范围、验收门槛及独立授权边界。

输出：短起点 + 持久任务清单。结论：文档归档适合主代理整合、一个 worker 独立审查，避免多人重复撰写同一事实。

## 可产品化机会（建议清单，均未在本轮实现）

| 编号 | 产品化点 | 用户收益/最小范围 | 验收与边界 |
|---|---|---|---|
| O1 | 发布/安装/市场版本面板 | 一眼区分本机版本、最新归档和目录目标 | 展示核对时间和来源；不能凭描述判断已更新；市场集成为独立项目 |
| O2 | 统一语义状态组件 | 收发列表、详情、工具卡片用一致状态 | 覆盖投递与任务两类；明暗主题/键盘/色盲可辨；对应 A1 |
| O3 | 能力驱动的收件人详情 | 没有设备数据时不展示一排未知 | 不支持/未配置/失败/过期可区别；不添加假在线/IP；对应 A3/B1 |
| O4 | 友好错误与诊断视图 | 用户知道下一步，维护者能排查 | 默认不泄露认证值/栈/路径；诊断仍受权限与脱敏约束；对应 A4 |
| O5 | 迁移预检与恢复验证器 | 自动盘点版本、归档、激活依赖和回退兼容 | 默认只读；停服务/备份/切换仍需授权；不得自动回写 T0 邮箱 |
| O6 | 声明式端到端验收工具 | 可重复验证发送、回执、断连和重启 | 隔离 home、明确角色和故障阶段、稳定标记、私有原始证据与公开摘要分离 |
| O7 | 防重复发送与结果核实流程 | 网络不稳时仍知道消息是否已提交 | 服务端幂等契约先行，UI 不自行宣称恰好一次；未知结果不可盲目重试 |
| O8 | 可接续的任务/证据模板 | 新任务不重新梳理整段历史 | 当前状态与历史分开、固定任务编号、证据类型/时间明确、保留未执行状态 |

优先顺序：O2/O4 随 A 类 UI 任务落地；O3 的能力呈现随 A3，真实设备/IP/心跳仍属于 B1；O8 可先复用文档格式。
O1/O5/O6/O7 应单独立项评估，不能借文档整理自动增加服务或扩大生产权限。
