## 踩坑与解决过程

| 编号 | 现象/问题 | 原因与处理 | 最终状态与防复发 |
|---|---|---|---|
| R01 | 双主机 worker 发 error 被拒绝 | 把发起方当成执行方；主代理按“assignee → origin”重验，再补另一方向任务 | 已验证；原任务 failed 与 error 通知 submitted 分别断言 |
| R02 | worker 未覆盖 Hub 断连 | 断开窗口过短，轮询时已恢复；主代理在确认 down 期间直接调用双方 MCP | 已补验；故障注入采用阶段同步，不能将 not_run 计为通过 |
| R03 | 旧 UI 共装统一插件失败 | 两包注册相同 UI loader；先移除独立 UI 再安装统一包 | 已验证；保持一个 MCP、一个 UI，升级前验证精确旧版回退包 |
| R04 | provider 原生模块的 Node 兼容风险 | DSH 与 provider 使用不同 Node；新 provider 独立安装并由显式 wrapper 启动 | 已验收；不复制别机 node_modules，不覆盖旧运行时 |
| R05 | 只停 DSH 后服务又被拉起 | LAN socket 接到连接，经代理重新激活服务；暂停入口 socket、代理与主服务 | 已解决；停写以实际进程/文件占用核对为准，不能只相信 stop 返回码 |
| R06 | 主数据库哈希不能证明备份完整 | WAL 可能含新提交；最终停写 checkpoint + SQLite backup API +只读恢复验收 | 已验证；主文件哈希仅用于变更检测 |
| R07 | 回退旧数据库可能丢新邮件 | 新版启动或发送可能已接受写入；新库上验证旧 provider 能读、能 ack | 已验证隔离软件回退演练，未执行生产回退；新邮件存在或结果未知时保留当前邮箱 |
| R08 | 旧 UI 浏览器检查超时 | 测试沿用了新版页面标记；实际旧页已显示，调整旧版只读探针 | 测试适配问题；按真实版本能力定位，不据此修改产品 |
| R09 | L2 刷新失败测试找不到新行 | 刻意阻断读取，却要求历史行可读；界面实际已显示“提交成功但刷新失败” | 通过收件人 inbox 核实已接受消息后恢复刷新，未重发；不误判为发送失败 |
| R10 | 测试假设 Explorer 标签存在 | 当前布局不保证该标签；改用离开页面再返回测试卸载/重挂载 | 已验收；不把该结果夸大为所有标签关闭按钮已实测 |
| R11 | 重启后首个浏览器访问拒绝连接 | systemd start/restart 返回时 HTTP 尚未就绪 | 就绪后复验通过；有界 ready 探针待工具化，避免盲目延长 sleep |
| R12 | TLS 正常挑战不等于 HTTPS 登录验收 | 已知路由返回有效证书和 401；环境 DNS 不可用，未做公网认证浏览器流程 | 保留限制；未改 DNS/认证，也不把 loopback 浏览器通过当公网全链路通过 |
| R13 | 配对输入曾被抽屉裁剪 | 固定高度与内容溢出；引入受约束滚动区 | 历史阶段已修；真实 Chrome/Firefox 检查滚动后的控件可见性 |
| R14 | 激活令牌路径与远端身份适配错误 | journal 路径相对 provider home；远端身份需用认证返回值而非旧环境值 | 历史阶段已修，详见 P1.2；保持路径归属和身份来源回归测试 |
| R15 | 表单测试点到错误输入框或未就绪按钮 | DSH 对话输入与邮件输入并存；控件加载有先后 | 限定 Agent Mail 区域并等待 enabled，不触发模型回合 |
| R16 | 市场描述旧但本地版本新 | 发布归档、本地安装、目录 PR、市场缓存各自独立 | 版本已核实，目录待上游；不能靠绿色“已安装”判断可下载版本 |
| R17 | 目录构建失败需要独立归因 | 当时构建失败来自其他既存条目的 added-date 派生 | 本地目标 YAML/README 验证通过；未改无关条目，后续重新核对远程状态 |
| R18 | 收件人详情一排未知 | provider 不采集设备/IP/心跳；列表曾硬编码连接未知；本地模式不适用 Hub | A3 已改为能力说明；真实设备/心跳仍属 B1 |
| R19 | UI 大量技术术语和重复说明 | 内部模型直接映射到页面；任务结果、投递状态和在线状态混在阅读流程中 | A0–A7 已提交 `0.2.1`；剩余缺口见逐页清单 |
| R20 | 误判市场只能从 npm 安装 | 需检查具体 market 版本的安装解析实现；已确认支持匹配仓库的 Release tarball | 文档已纠正；以后核对实际解析器及下载字节，不从 npm 缺失推断不可安装 |
| R21 | 指定 worker 类型或新任务工具不可用 | 某历史阶段 luna-worker 未注册；后来创建新任务工具也不可调用 | 如实记录替代角色/可粘贴起点，不宣称未发生的委派或任务创建 |
