| 来源 | 呈现边界与验证 |
|---|---|
| 主错误、发送、详情 | host API allowlist + `requestMailApi` 固定映射；合同分别注入普通异常、未知代码、JSON 敏感字段和断网错误。保留 UI 自己生成的「提交已成功，但刷新失败」事实。 |

| 提示文本 | `sanitizePublicError` 仅作为附加净化，覆盖引号键和短值；不把正则净化作为未知异常的安全边界。 |

浏览器请求 65 秒、host 工具等待 60 秒到期后返回「超时，请核实结果」。即使 fetch 正文或 provider
不响应 AbortSignal，也停止等待且不自动重发。超时不能证明操作未执行；草稿及后续核实按未知结果处理。
合同覆盖挂起 fetch、挂起响应正文和忽略 abort 的 provider，并断言调用只有一次。

真实浏览器还暴露了发送成功后的刷新竞态：第一次 `/status` 失败会使身份暂时未知，
原先的清空逻辑连本地已提交记录也删除。现保留本地提交事实及正文，暂时隐藏持久历史并停止身份未核实的
发送/历史读取；恢复为同一身份时保留，确认切换身份时清空，旧身份的在途响应按代次丢弃。
浏览器在第一次提交后立即注入状态请求失败，验证成功徽标、正文和草稿之外的提交记录仍在，
且浏览器和真实 provider 都只有一次发送。身份切换及陈旧响应另由合成组件状态探针验证。

未安装管理宿主时，真实 DSH 的静态 POST fallback 返回空正文 405。适配器现将它识别为未配置；
带结构化错误的 405 仍按管理错误处理。合同与真实侧栏均验证了这个区别。

| 待保存、确认与取消 | 真正 redeem 后显示 pending_save；未确认身份时保存禁用；一次配对取消后服务器与 UI 返回 cancelled。浏览器重载和真实 DSH 重启分别恢复待保存记录。 |

| 保存待激活→重启→恢复→激活 | 用管理宿主支持的另一当前配置运行，浏览器选择尚未运行的目标。真实 commit 返回 `state=saved, save_state=saved, activation_state=restart_required`，页面显示等待激活且保留恢复信息。将隔离宿主重启到已保存目标，重新登录恢复 saved，再实际点击激活，服务器返回 active。重启后只有一次 status 和一次 activate，没有重复 redeem/commit；真实 MCP 身份与保存身份相同，TLS 验证为真。 |
| 保存成功、响应未到达页面→重启恢复 | fetch 先取得真实服务器 commit 的 saved/active 响应，再暂缓交给 UI；不改响应、不写入恢复元数据。页面仍等待时重启隔离 DSH，再登录仅查询一次 status 即恢复 active，原身份一致，恢复句柄清除，没有重复配对或保存。 |
