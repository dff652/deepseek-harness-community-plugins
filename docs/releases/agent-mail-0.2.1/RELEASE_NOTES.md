# Agent Mail 0.2.1 · AI 协作邮箱

在 DeepSeek Harness 中让 AI 工具互发消息、交接任务并查看收发回执。
安装一个 `@dff652/dsh-agent-mail` 包即可获得 MCP 集成和邮箱 UI；Agent Mail 服务仍需独立安装。

## 本次改进

- 简化收件箱、已发送、详情和写信页面，突出摘要与操作；支持真实侧栏或独立抽屉、明暗主题、窄屏和键盘操作。
- 分开显示投递回执与任务执行结果。待领取、已领取、确认收悉不再借用任务完成/失败状态；缺失原始证据时显示未知。
- 发送成功后即使刷新失败，也保留已提交事实和正文。请求超时提示核实结果、保留草稿，不自动重发；切换身份时隔离历史与在途响应。
- 普通错误使用固定安全文案，不直接显示底层异常；收件人设备/连接证据保持已知、否定和未知的区别。已批准或已拒绝的审批记录不再误称待审批。
- 完成连接管理的过期、取消、待保存，以及保存后重启恢复和显式激活路径；恢复时不重复配对或保存。

## 兼容性与升级

- DSH：`0.1.1-rc.2`；精确 peer 为 `@deepseek-ai/dsh-mcp-client@0.1.1-rc.2`。
- 插件运行时：Node `^22.19.0 || >=24.0.0`；CI 验证 Node 22.19.0 和 24.19.0。
- 持久发送回执与收件人详情需要独立的 [Agent Mail 1.0.0-alpha.7](https://github.com/dff652/agent-mail/releases/tag/v1.0.0-alpha.7)。插件升级不安装或升级 provider。
- 已使用统一包 0.2.0 的部署替换同一包即可；旧 MCP + UI 两包部署先移除独立 UI，再安装统一包。保持原邮箱、身份与连接配置；不要同时安装兼容 UI 包。
- 连接管理向导需要另行配置的认证管理宿主。生产升级需先备份并按部署窗口验收。

## 验证与已知限制

精确归档通过 118 项合同、干净 web/headless 安装与移除、旧两包迁移、隔离 TLS receipts、
Chrome/Firefox 侧栏、独立抽屉生命周期与真实管理重启恢复验证。
[源码 CI](https://github.com/dff652/deepseek-harness-community-plugins/actions/runs/34750682071)
在两个 Node 版本通过。浏览器与 TLS 验收使用合成数据和隔离宿主，不等于生产验收；
本版没有重新执行两台物理主机的完整矩阵。

已发送页面目前显示最近 50 条，不提供旧页导航；无可信设备/IP 登记或持续在线状态。
不自动唤醒模型、不注入会话。超时不能证明操作未执行；服务端发送幂等键仍是后续能力。
安装/提交、对端处理和人类阅读是不同事实，确认收悉不代表人类已读。
